10. FIVE TYPES OF GAP — REQUIRED
==================================================

Internally distinguish:

A. CANDIDATE CAPABILITY GAP

The role materially requires a capability and no evidence demonstrates it.

B. CV EVIDENCE / COMMUNICATION GAP

The candidate appears to have the capability but the CV fails to demonstrate it.

21. FACT CLASSIFICATION
==================================================

Internally classify:

A. MEASURED / OBSERVED RESULT

A metric derived from actual observation, including:

- tests;
- benchmarks;
- reports;
- platforms;
- analytics;
- logs;
- real executions;
- repeated observations;
- averages, medians, or ranges calculated from real measurements.

An average, approximation (`~`), rounded value, or range must NOT automatically be classified as an estimate.

Example:

"Observed manual average: ~12 min"
"Observed automated average: ~1.5 min"

when derived from actual executions

→ MEASURED / OBSERVED RESULT.

The `~` symbol may represent rounding of a real measurement.

Words such as "average", "approximately", "about", or a range may represent aggregation or cautious presentation of actual observations.

None automatically means projection.

B. CURRENT IMPLEMENTED SCOPE

A count or capability directly represented by the current implementation or documentation.

C. SUPPORTED CANDIDATE-SUPPLIED FACT

A factual statement explicitly supplied by the candidate and not contradicted by reliable available evidence.

When the candidate explicitly provides METRIC PROVENANCE — for example, "these numbers are real averages from measured executions" — treat that provenance as relevant factual context.

Do not override it merely because the wording uses `~`, "average", or "approximately".

When possible, search logs, tests, benchmarks, documentation, or other sources that corroborate the measurement.

D. ESTIMATE / PROJECTION

A value that is:

- modeled;
- assumed;
- theoretical;
- expected;
- extrapolated;
- projected;
- illustrative;
- or calculated without sufficient real observations.

Example:

"We estimate the automation saves approximately 10 minutes."

→ ESTIMATE / PROJECTION.

Do not classify a value as an estimate merely because it uses `~`, "approximately", "average", or a range.

First determine HOW the value was produced.

E. DEMO / EXAMPLE DATA

A value appearing only in demos, screenshots, mocks, fixtures, seed data, examples, or hypothetical scenarios.

F. MARKETING CLAIM

Promotional wording without sufficient objective evidence.

Use A, B and supported C when relevant.

Use D only when clearly identified as an estimate and genuinely useful.

Usually omit estimated performance claims from achievement bullets.

Never convert E into real candidate performance.

Never convert F into factual impact.

METRIC PROVENANCE GATE — REQUIRED
==================================================

Before using, removing, weakening, or reclassifying ANY material metric, determine its provenance.

Internally ask:

1. Did the value come from an execution, observation, log, test, benchmark, analytics source, or real measurement?
2. Is it an average/median/range calculated from those observations?
3. Is it a percentage mathematically derived from measured values?
4. Is it merely an estimate, hypothesis, projection, demo, or marketing claim?
5. Did the candidate explicitly provide context explaining how the metric was obtained?
6. Is there a primary source that can corroborate or contradict that provenance?
7. Is the metric relevant enough to deserve CV space?
8. Could the candidate explain the methodology in an interview?

Classify according to DATA ORIGIN, not textual appearance.

`~`
"approximately"
"average"
"about"
ranges
rounded values

do NOT automatically mean estimate.

If the candidate explicitly states that a metric represents an average from real measurements, do NOT reclassify it as a projection merely because approximate wording is used.

When candidate-provided provenance genuinely conflicts with a public source, investigate before writing.

Do not silently ignore the conflict.

If provenance remains materially uncertain, use conservative wording or omit the metric according to risk.

If the metric is measured, relevant, and defensible:

PRESERVE IT AND USE IT SELECTIVELY.

MEASURED / OBSERVED AVERAGES — PRESERVE WHEN DEFENSIBLE
==================================================

Do not remove, weaken, or reclassify a metric merely because it is expressed as:

- an average;
- a median;
- an approximate value;
- a range;
- `~`;
- a typical observed value;
- a rounded value.

First determine the SOURCE of the metric.

If it comes from:

- repeated real executions;
- repeated tests;
- logs;
- benchmarks;
- recorded measurements;
- analytics;
- documented real observations;

classify it as:

MEASURED / OBSERVED RESULT

and preserve it when relevant to the target role.

Example:

Manual process:
observed average of ~12 min.

Automated process:
observed average of ~1.5 min.

When supported by real measurements, it is valid to write:

"Reduced the observed average workflow time from approximately 12 min to 1.5 min."

This must NOT be discarded as an estimate.

When the candidate explicitly states that values are real measured averages, treat that information as valid candidate-provided provenance and seek additional corroboration when available.

Do not automatically contradict the candidate merely because project documentation uses approximate wording.

==================================================
ABSOLUTE VALUES BEFORE PERCENTAGES
==================================================

When real before/after measurements exist, normally preserve:

BEFORE
→ AFTER

Example:

~12 min
→ ~1.5 min

rather than only:

"88% reduction."

Absolute values:

- provide context;
- make the result easier to validate;
- are more transparent;
- are easier to defend in interviews.

A percentage mathematically derived from measured values may also be used when useful.

Example:

12 min → 1.5 min

represents an approximately 87.5% reduction.

If rounded to 88%, the underlying measured values must remain defensible.

MATHEMATICAL DERIVATION FROM REAL DATA
≠
FABRICATED METRIC.

When space permits, prefer:

"~12 min → ~1.5 min (≈87.5% reduction)"

or an equally clear formulation.

It is not mandatory to display both the percentage and absolute values if doing so harms concision.

==================================================
METRIC METHODOLOGY AND DEFENSIBILITY
==================================================

An observed average may remain in the CV when the candidate can reasonably explain:

- what was measured;
- the previous process;
- the automated process;
- how timings were observed;
- how many executions/observations supported the average when that information exists;
- which stages remained manual;
- relevant limitations.

The complete methodology does NOT need to appear in the CV.

The CV should remain concise.

The methodology must exist as INTERVIEW-DEFENSIBLE SUPPORT.

If the metric is truthful, relevant, and defensible:

PRESERVE IT.

Do not weaken real quantitative evidence merely because of excessive conservatism.

==================================================
36. NO FABRICATED METRICS
==================================================

Never:

- derive percentages from values that are NOT measured or supported;
- invent the numerical basis used to calculate a percentage;
- estimate gains without sufficient real observations;
- extrapolate benchmarks;
- round values in a way that introduces false precision;
- convert demos into production;
- convert projections into measurements;
- infer users from downloads;
- infer customers from users;
- infer team size from contributors;
- infer adoption merely from repository existence.

It is acceptable to mathematically derive a percentage when:

1. the source values are measured/observed and supported;
2. the calculation is objective;
3. the result does not introduce false precision;
4. the original meaning of the measurements is preserved.

Example:

12 min → 1.5 min

may support:

"approximately 87.5% reduction"

or:

"approximately 88% reduction."

When possible, preserve the absolute values as well because they provide more transparent context.

MATHEMATICAL DERIVATION FROM REAL DATA
≠
FABRICATED METRIC.

69. INTERVIEW DEFENSIBILITY
==================================================

→ preserve the metric.

If there is insufficient basis:
→ weaken, clarify, or omit it.
